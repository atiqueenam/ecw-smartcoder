# eCW SmartCoder

Central GitHub hosting for the common Tampermonkey loader and client-specific SmartCoder scripts.

## Install the common loader

After this repository is uploaded, open this URL in Chrome with Tampermonkey installed:

<https://raw.githubusercontent.com/atiqueenam/ecw-smartcoder/main/loader/SmartCoder-Loader.user.js>

Tampermonkey will show an installation page. Install only this common loader and disable any separately installed Getwell or Hasan Sheikh scripts to avoid running a client twice.

## How updates work

- The first visit downloads the client registry from GitHub.
- Selecting a client downloads and verifies that client's script, then stores it locally.
- Ordinary page navigation uses the saved registry and script without contacting GitHub.
- A browser reload, including `Ctrl+Shift+R`, checks the registry for changes.
- The **Check updates / Refresh clients** button provides an explicit and reliable update check.
- A changed script downloads only when its version or SHA-256 checksum changes.
- Every browser profile receives a random local user ID. The ID is not sent to GitHub.

Browsers do not expose a dependable difference between `F5` and `Ctrl+Shift+R` to page JavaScript, so either kind of reload checks for updates. The button is the clearest method.

## Add a client

1. Copy an existing client folder under `clients/` and give it a lowercase ID, for example `clients/new-clinic/`.
2. Put the client's script in that folder as `smartcoder.js`.
3. Edit `client.json`:

```json
{
  "id": "new-clinic",
  "name": "New Clinic",
  "version": "1.0",
  "entry": "smartcoder.js",
  "enabled": true
}
```

4. Commit both files to `main`.
5. The **Update client registry** GitHub Action validates the JavaScript, calculates its checksum, updates `registry/clients.json`, and commits the registry.
6. Users press **Check updates / Refresh clients** or reload. The new client appears automatically.

## Update an existing client

1. Replace that client's `smartcoder.js`.
2. Increase the version in the same folder's `client.json`.
3. Commit both changes together.
4. Wait for the green check mark on the GitHub commit. This means the registry workflow succeeded.
5. Tell affected users to press **Check updates / Refresh clients** or use `Ctrl+Shift+R`.

## Remove a client from the dropdown

Change `"enabled": true` to `"enabled": false` in its `client.json` and commit the change. The workflow regenerates the dropdown registry without deleting the client's files.

## Security and privacy

- This is a public repository. Never commit patient information, passwords, cookies, access tokens, or private keys.
- The loader verifies downloaded scripts against SHA-256 checksums generated by the repository workflow.
- Anyone who gains write access to this repository could change code that runs in eClinicalWorks. Enable two-factor authentication on the GitHub account and restrict collaborator access.
- The local user ID is for local identification only and is not an authentication mechanism.
